# Задача для облачного ChatGPT: очередь и goal

Это описание следующей разработки, не утверждение о готовых функциях. Исходная рабочая база: расширение 1.3.1. Требуется добавить очередь и режим цели с поведением, похожим на очередь задач в Codex Desktop, сохранив существующие защиты и перенос при лимите чата.

## Очередь

Пользователь добавляет отдельные сообщения, видит порядок и состояние, может редактировать/переставлять ещё не отправленные, приостанавливать, возобновлять и удалять их. Не считывать черновик в очередь автоматически: добавление должно быть явным действием пользователя.

Базовая очередь отправляет следующее сообщение после завершения предыдущего ответа. Для поведения как в Codex Desktop отдельно проработать явную кнопку Steer / «Отправить сейчас» во время активной генерации, если режим ChatGPT это поддерживает. Это отдельное действие пользователя, а не повод автоматически отправлять активный черновик. В плане явно обозначить, входит ли Steer в первый этап; без него не заявлять полную эквивалентность Codex Desktop. Ручное взаимодействие пользователя должно иметь приоритет; не отправлять и не затирать его ввод.

Состояние сохраняется локально: стабильный ID очереди/элемента, точный текст и собственные вложения, порядок, источник/текущий чат, номер попытки и операция отправки. Проработать переходы pending → preparing → sending → confirmed → waiting/completed и отдельное состояние unknown. При восстановлении `sending` нельзя автоматически превращать в pending и отправлять повторно.

Один элемент должен иметь одного исполнителя даже при двух вкладках одного чата, повторной доставке сообщений, обновлении расширения или пробуждении worker. Существующие повторы ошибок не должны потреблять следующий элемент очереди или создавать второй независимый цикл отправки.

## Goal

Пользователь явно задаёт цель и условия остановки. Предусмотреть start/pause/resume/stop, сохраняемые ограничения числа продолжений и времени, а также понятную причину остановки. Автопродолжение не должно быть бесконечным по умолчанию.

Goal ожидает подтверждённого результата текущего ответа и только затем решает, нужна ли следующая разрешённая команда. Предложить критерии завершения и явно отделить заявление модели «готово» от независимо проверенного выполнения. Не утверждать, что расширение проверило репозиторий/CI/внешнюю систему, если у него нет такого доступа.

Определить приоритет ручного сообщения, явно поставленного элемента очереди и продолжения goal. Должен работать один координатор отправок, а не три конкурирующих цикла. Все автоматические тексты проходят те же persist/authorize/editor-check/one-click/confirm проверки, что текущие повторы и handoff.

## Лимит длины чата

Существующий механизм открывает новый чат в той же вкладке, переносит два последних сообщения пользователя и два финальных ответа ассистента в исходном порядке, прикладывает большой контекст файлом, выбирает `max` и переносит название с номером продолжения.

Добавить к этому устойчивую связь очереди и goal с цепочкой чатов. Сохранить состояние **до** перехода. После подтверждения handoff привязать продолжение к новому chat ID, сохранив ID элементов, бюджет и журнал старого/нового адреса. Неподтверждённую передачу или отправку не повторять вслепую.

Не превращать все неотправленные сообщения очереди в инструкции внутри handoff-контекста: это нарушит их порядок. Передать необходимую цель/текущее состояние, а оставшиеся элементы сохранить как очередь. Не отправлять повторно уже подтверждённый элемент. Черновик и пользовательские вложения сохраняются отдельно и не становятся payload автоматически.

Счётчик продолжений не сбрасывается из-за неудачного переименования. Поддержать продолжение после остановки worker между каждым из этапов перехода, подготовки вложения, авторизации, клика, подтверждения и переименования.

## Проверки результата

- FIFO: один элемент → новое подтверждённое сообщение → завершение ответа → следующий элемент.
- Две вкладки, повторное событие, повторная инъекция и перезапуск worker не создают дубликаты.
- Crash/timeout после клика даёт unknown и остановку, а не автоматическую повторную отправку.
- Повторы ошибок ограничены, старый блок ошибки не считается новым сбоем, ручной ввод сохраняется.
- Pause/stop и бюджеты goal переживают восстановление.
- При лимите чата очередь/goal продолжаются только в подтверждённом новом чате, без потери очереди и повторной передачи истории.
- Старые данные 1.2.7 мигрируют без потери журнала, черновиков, блокировок и существующих handoff.
